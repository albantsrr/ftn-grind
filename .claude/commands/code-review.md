🎯 Objectifs de la review

Analyser la structure du projet et identifier :

Les incohérences dans l’organisation ou les dépendances.

Les fichiers inutiles (code mort, doublons, ressources non référencées).

Les problèmes de cohérence dans le style, la logique ou la nomenclature.

Proposer et appliquer les améliorations nécessaires :

Nettoyer le code et supprimer ce qui est superflu.

Réorganiser les répertoires si cela améliore la clarté.

Uniformiser les conventions de nommage et le style de code.

Documenter les changements :

Décrire clairement les modifications apportées et pourquoi.

Fournir une liste de recommandations pour la suite.

🧩 À la fin, je veux que tu me rendes :

✅ Une version corrigée et réorganisée du code.

📋 Un résumé clair des changements effectués.

🚀 Une feuille de route avec les prochaines étapes (par exemple : tests à renforcer, CI/CD à mettre en place, documentation à compléter, etc.).
